# Web Launch Audit (ตรวจเว็บแบบผู้ใช้จริง 20 จุด)

แนวคิด: อย่าสั่ง AI แค่ว่า "ทำให้เว็บสวยขึ้น" ให้สั่งว่า **"ตรวจเว็บนี้เหมือนคนที่จะเข้ามาใช้งานจริง"**
แล้วให้รายงานปัญหาออกมาก่อน ยังไม่ต้องแก้

## กฎหลัก

1. **รายงานก่อน แก้ทีหลัง** ห้ามแก้โค้ดระหว่างตรวจ จบด้วยรายงาน แล้วถามผู้ใช้ว่าจะให้แก้ข้อไหน
2. **ทุกปัญหาต้องมีหลักฐาน** บอกหน้า/route, ไฟล์:บรรทัด (ถ้ามี), screenshot หรือสิ่งที่สังเกตได้ และวิธีทำให้เห็นปัญหาซ้ำ
3. **ห้ามเดา** ถ้าไม่ได้รันเว็บจริงหรือไม่ได้อ่านโค้ดส่วนนั้น ให้ใส่ป้ายว่า "ยังไม่ได้ยืนยัน" อย่ารายงานว่าเป็นปัญหาแล้ว
4. มองจากมุมผู้ใช้ก่อน มุมโค้ดทีหลัง

## ขั้นตอน

1. **ทำความเข้าใจเว็บ**: อ่าน README, routes/pages, เมนูนำทาง แล้วสรุปเป็นประโยคเดียวว่าเว็บนี้ทำอะไร ใครใช้ และ "งานหลัก" (core task) ของผู้ใช้คืออะไร
2. **รันเว็บจริงถ้าทำได้**: start dev server แล้วใช้ Playwright/Chromium เปิดดู 2 ขนาดจอ
   - Desktop 1440×900
   - Mobile 375×812 (และ 320 กว้างสุดแคบ ถ้ามีเวลา)
   - เก็บ screenshot ไว้ใน scratchpad เพื่อใช้เป็นหลักฐาน
   - ถ้ารันไม่ได้ ให้ตรวจจากโค้ดแทน และระบุในรายงานว่าตรวจแบบ static
3. **ไล่ตรวจ 20 จุดด้านล่าง**
4. **เขียนรายงาน** ตามรูปแบบท้ายไฟล์

## 20 จุดตรวจ

### A. ดีไซน์ (ความสม่ำเสมอ)
1. **สี**: ใช้สีจากชุดเดียวกันไหม หรือมี hex กระจัดกระจาย สีปุ่มหลัก/ลิงก์ตรงกันทุกหน้าไหม contrast ข้อความผ่าน WCAG AA (4.5:1) ไหม
2. **ฟอนต์**: จำนวนฟอนต์และขนาดตัวอักษรเป็นระบบไหม heading มีลำดับชัด (h1→h2→h3) ไหม
3. **ระยะห่าง**: margin/padding ใช้สเกลเดียวกันไหม (เช่น 4/8/16/24) การจัดแนวตรงกันไหม
4. **ปุ่ม/คอมโพเนนต์**: ปุ่มแบบเดียวกันหน้าตาเหมือนกันทุกที่ไหม มีสถานะ hover / focus / disabled ครบไหม

### B. มือถือ
5. **ไม่ล้นจอ**: ไม่มี horizontal scroll ที่ 375px และ 320px รูปกับตารางไม่ทะลุจอ
6. **เมนู**: hamburger/nav เปิดปิดได้ ปิดได้ทุกวิธี และเข้าถึงทุกหน้าได้
7. **ปุ่มกดง่าย**: tap target ขนาด ≥ 44×44px และไม่ชิดกันจนกดพลาด
8. **อ่านง่ายและกรอกง่าย**: ตัวอักษร ≥ 16px (ไม่งั้น iOS จะ zoom ตอนแตะ input) ใช้ input type ที่ถูก (email, tel, number) และมี viewport meta

### C. สถานะต่าง ๆ (States)
9. **Loading**: ตอนรอข้อมูลมี skeleton/spinner ไหม หรือจอว่างเปล่า/กระพริบ ปุ่ม submit กันกดซ้ำไหม
10. **Empty**: ตอนไม่มีข้อมูล บอกผู้ใช้ไหมว่าทำอะไรต่อได้ (มี CTA)
11. **Validation**: กรอกผิดแล้วข้อความ error อยู่ใกล้ช่องที่ผิด อ่านเข้าใจ และค่าที่กรอกไว้ไม่หาย
12. **Error/ระบบล่ม**: API ล่ม, 404, 500, offline แล้วผู้ใช้เห็นอะไร มีทางให้ลองใหม่หรือกลับหน้าหลักไหม ต้องไม่เห็น stack trace

### D. การใช้งานจริง (End-to-end)
13. **Core flow**: เดินตั้งแต่เข้าเว็บจนทำงานหลักเสร็จ (เช่น สมัคร → ใช้งาน → สำเร็จ) ได้โดยไม่ติด และนับว่ากี่คลิก
14. **ลิงก์และปุ่มทุกตัว**: ไม่มีลิงก์เสีย ไม่มี `href="#"` ที่ไม่ทำงาน ไม่มีปุ่มที่ไม่มี handler ไม่มีหน้า placeholder หรือ lorem ipsum ค้างอยู่
15. **Feedback หลังทำงาน**: บันทึก/ส่งแล้วมี toast หรือข้อความยืนยัน และกด back/refresh แล้วข้อมูลไม่พังหรือไม่ส่งซ้ำ
16. **Console และ Network**: ไม่มี JS error ใน console ไม่มี request ที่ 4xx/5xx และไม่มี asset ที่ 404

### E. ความชัดเจนก่อนเปิดเว็บ
17. **เข้าใจภายใน 5 วินาที**: hero/หน้าแรกบอกชัดไหมว่าเว็บนี้ทำอะไรและให้ใคร
18. **หน้าละหนึ่งเป้าหมาย**: แต่ละหน้ามี primary CTA เดียวที่ชัด ไม่มีปุ่มแย่งความสนใจกัน
19. **ข้อความ/ภาษา**: ไม่มีคำผิด ใช้คำเรียกสิ่งเดียวกันตรงกันทุกหน้า และไม่ปนภาษาโดยไม่ตั้งใจ
20. **ความพร้อมเปิดตัว**: มี `<title>` และ meta description แยกแต่ละหน้า มี favicon และ OG image สำหรับแชร์ใน LINE/FB มีข้อมูลติดต่อหรือ privacy (ถ้าเก็บข้อมูลผู้ใช้) และไม่มี secret/API key หลุดใน frontend

## รูปแบบรายงาน

```markdown
# Web Launch Audit — <ชื่อเว็บ>
เว็บนี้คือ: <1 ประโยค> | Core task: <...> | วิธีตรวจ: runtime / static

## สรุป
- 🔴 Blocker: N  🟠 Major: N  🟡 Minor: N
- ผ่าน: X/20 จุด
- ต้องแก้ก่อนปล่อย: <3 ข้อสำคัญสุด>

## ตารางผล 20 จุด
| # | จุดตรวจ | ผล (✅/⚠️/❌/❓) | หมายเหตุสั้น |

## รายการปัญหา (เรียงจากรุนแรงสุด)
### [🔴] <ชื่อปัญหา>  — จุดที่ #N
- **หน้า:** /checkout (mobile 375px)
- **หลักฐาน:** <สิ่งที่เห็น / screenshot / ไฟล์:บรรทัด / console log>
- **ทำให้เห็นซ้ำ:** <ขั้นตอน>
- **ผลต่อผู้ใช้:** <ผู้ใช้เจออะไร>
- **วิธีแก้ที่แนะนำ:** <ทำอะไร ที่ไฟล์ไหน>
```

ระดับความรุนแรง:
- 🔴 **Blocker**: ผู้ใช้ทำงานหลักไม่สำเร็จ หรือมีปัญหาความปลอดภัย/ข้อมูลหาย
- 🟠 **Major**: ทำได้แต่สับสน หรือใช้บนมือถือลำบาก
- 🟡 **Minor**: ความสวยงามหรือความสม่ำเสมอ

ปิดท้ายรายงานด้วยคำถาม: **"จะให้แก้ข้อไหนก่อนครับ (แนะนำ: Blocker ทั้งหมด)"** แล้วหยุดรอคำตอบ

## ใช้กับแค่บางด้าน
ถ้าผู้ใช้ระบุด้านมา เช่น "ตรวจแค่มือถือ" ให้ตรวจเฉพาะหมวดนั้น แต่ใช้รูปแบบรายงานเดิม
